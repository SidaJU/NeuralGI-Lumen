Notes 7：log 域训练与 Jensen 偏差

为什么 NN 输出的 GI 会系统性偏暗？—— 从数学原理到项目每一行代码

1. Jensen 不等式是什么

一句话：对"向上弯"的（凸）函数，先平均再算函数 ≤ 先算函数再平均。

最简数字例子（凸函数 x²）

做法计算结果
先平均，再算函数1 和 3 平均 = 2，然后 2²4
先算函数，再平均1²=1，3²=9，再平均 (1+9)/25
f(平均值) = 4  ≤  平均值(f) = 5
先平均再算，结果更小。

生活类比：奖金

奖金 ∝ 业绩²（凸函数）。业绩波动越大（1 和 3 vs 都是 2），"先算再平均"比"先平均再算"多得多。

业绩先平均再算先算再平均差
1 和 3（波动大）2² = 4(1+9)/2 = 51
2 和 2（无波动）2² = 4(4+4)/2 = 40

关键：波动（方差）越大，差距越大；没有波动就完全相等。

2. 几何图解（为什么曲线在中点更低）

3. 为什么会这样：凸函数"放大差距"

1 离平均 2 差 −1 → 1²=1（比 4 少 3）
3 离平均 2 差 +1 → 3²=9（比 4 多 5）
大的一侧多赚 5，小的一侧只亏 3 —— 不对称 → 平均后偏大

凸函数的本质：离平均越远的大值，被放大得越厉害，所以"先算函数再平均"更大。

① 编码端：把线性 radiance 压到 log 域

def log_normalize(x: np.ndarray) -> np.ndarray:
    """HDR radiance -> O(1) 范围."""
    return np.log1p(np.maximum(x, 0.0)).astype(np.float32)

② 模型输出：也在 log 域（残差也在 log 域）

train/model.py:83-95（forward）

def forward(self, x: torch.Tensor) -> torch.Tensor:
    out = self.net(x)
    if self.use_residual:
        # 通道 [12:15] 是中心 probe 的 log1p(radiance)，即"未滤波的输入"
        center = x[:, 12:15]          # ← 因为特征已是 log 域，center 也是 log 域
        out = center + out            # ← 输出仍是 log 域
    return out
所以模型输出是 log 域的值（不是一个"线性颜色"）。这一点是理解偏暗的关键。

引擎里的那一行（NSPFWriteBack.usf:48）就是你看到"GI 偏暗"的地方： 
const float3 Radiance = max(exp(LogOut) - 1.0, 0.0);   // 等价于 expm1
HLSL 没有 expm1，所以用 exp(x) - 1 实现 —— 数学上一样，Jensen 偏差也一模一样。

6. 偏了多少？（数学：lognormal 修正）

数学上有现成结论：如果 log(X) 的均值 = μ、方差 = σ²，那么

真实期望亮度 E[X] = exp(μ + σ²/2)
而我们输出的是 exp(μ)
→ 少乘了 exp(σ²/2) 这个因子
σ²（log 域波动）偏暗因子 exp(σ²/2)相当于亮度只剩
0（无波动）1.0100%（不偏）
0.51.2878%
1.01.6561%
2.02.7237%

GI radiance 波动很大（暗 0.001 / 亮 10+，log 域跨好几倍）→ σ² 不小 → 偏暗可观。

7. 修复方案（先测量，再动手）

第 1 步：定量测量"暗了多少"

ratio = mean(pred_lin) / mean(gt_lin)      # 线性域均值比
med   = median(pred_lin / (gt_lin + 1e-6))  # 逐 texel 比值中位数
结果结论
ratio ≈ 0.7~0.9（或中位数明显 < 1）✅ Jensen 偏差坐实
ratio ≈ 1.0偏暗另有原因（GT 本身暗 / 欠拟合 / 无历史）

第 2 步：三条修复路径

① 全局常数（最快）

输出改为 exp(LogOut + K) - 1，K 先试 0.2~0.5，看画面。
需要同步改 Python 三处 + shader。

② lognormal 修正（推荐）

输出 exp(μ + σ²/2) - 1。
σ² 可用全局估计，或让网络多预测一个方差头。

③ 线性域训练（最严谨，但代价大）

去掉 log1p，直接在线性 radiance 上算 relative L2。
代价：动态范围回到 0.001~15，训练稳定性变差 —— 这正是当初引入 log1p 的原因。

改动要同步：引擎 shader（NSPFWriteBack.usf:48）与 Python 侧三处（eval_smoothness / visualize_b / run_infer）必须一起改，否则离线评估和引擎画面会对不上。
