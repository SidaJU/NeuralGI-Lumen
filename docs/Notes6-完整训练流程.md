## 1. 数据从哪来

### 1.1 三级展开（重点）

```
第1级: 一帧画面（1440 × 832 像素）
           ↓ 每 16×16 像素放 1 个 probe
第2级: probe 网格 = 90 × 35 = **3150 个 probe**

第3级: 每个 probe 内部是一张 8×8 的球面光照图
        8 × 8 = **64 个方向格子**，每格存 3 个数（RGB）

展开后:
    一帧样本数 = 3150 × 64 = **201,600**（全部）
    有效样本（过滤 depth ≤ 0）= 2656 × 64 = **169,984**（84.3%）
```

> **关键认知**：一个 probe **不是**一个数据，而是 **64 个数据**。
> 所以「一帧 3150 个 probe」→ 展开后是 20 万个样本。

### 1.2 采集的文件（每帧一组）

| 文件 | 形状 | 内容 | 来源 |
|---|---|---|---|
| `in.npy` | (280,720,3) | **滤波前** radiance（含噪点）| `CompositedScreenProbeRadiance` |
| `gt.npy` | (280,720,3) | **滤波后** radiance（较干净）| `ScreenProbeRadiance` |
| `hitdist.npy` | (280,720) | 射线命中距离 | `ScreenProbeHitDistance` |
| `depth.npy` | (35,90) | probe 深度 | `ScreenProbeSceneDepth` |
| `normal.npy` | (35,90,2) | 世界法线（八面体编码）| `ScreenProbeWorldNormal` |
| `wpos.npy` | (35,90,4) | 平移后世界坐标 | `ScreenProbeTranslatedWorldPosition` |
| `.json` | — | 相机矩阵 | View / Proj / PreViewTranslation |
| `meta.json` | — | 全局配置 | atlas 尺寸、probe 网格等 |

**形状含义**：
- `(280,720)` = 35×8 × 90×8 → **展开后的 probe atlas**（texel 级）
- `(35,90)` = probe 网格 → **probe 级**（每 probe 一个值）

### 1.3 样本单位（最小学习单位）★易混点

```
一个样本 = (probe, 方向格子) 对
         = atlas 里的一个 texel
         → 输出 3 个数（RGB radiance）

169,984 有效样本 = 2656 个有效 probe × 64 个方向格子
```

**⚠️ "像素" 这个词有两个不同含义，别搞混：**

| 名称 | 尺寸 | 一个格子覆盖多少屏幕像素 |
|---|---|---|
| **屏幕像素** | 1440 × 832 | 1 像素 |
| **probe** | 90 × 35 | **16×16 = 256 个屏幕像素** |
| **atlas texel** | 720 × 280 | —（一个 texel = 一个方向格子）|

```
一个 probe 覆盖屏幕上的 256 个像素
但它在 atlas 里展开成 8×8 = 64 个 texel（每个 texel = 一个方向格子）
```

**准确说法**：
- 学习单位是「**一个 probe 的一个方向格子**」，**不是屏幕像素**
- 一个屏幕像素只贡献 1/256 个 probe 的信息
- 说"格子"若指 **atlas texel** ✓ 正确；若指**屏幕像素** ✗ 差了 256 倍

**补充：虽然一个样本 = 一个格子，但输入不是孤立的**

模型看到的是以目标格子为中心的 **3×3 邻域切片**（跨 9 个 probe、**同一方向**），
学习"如何加权平均这 9 个值"来去噪 —— 这正好复刻 Lumen 的空间滤波逻辑。

## 2. ⭐ 56 维输入的组成（核心）

### 2.1 完整分解表

| 通道 | 维度 | 是什么 | 来自哪个数据 | 有什么用 |
|---|---|---|---|---|
| **[0:27]** | **27** | 3×3 邻域 radiance | `in` 的 3×3 邻域采样 | **空间上下文**。Lumen 的空间滤波就是"同方向、跨 probe"平均，网络必须看到邻居才能学会 |
| **[27:36]** | **9** | 3×3 邻域 hitdist | `hitdist` 的 3×3 邻域 | 区分"墙角 vs 开阔地"——决定该不该抹平 |
| **[36:45]** | **9** | 3×3 邻域 valid | `valid` 的 3×3 邻域 | 边界外的邻居是 padding 出来的，告诉网络别信它们 |
| **[45:52]** | **7** | 几何（log深度1 + 法线3 + 相对坐标3）| `depth` / `normal` / `wpos` | 这个点在空间里的位置和朝向 |
| **[52:55]** | **3** | 历史帧 radiance | 上一帧 `in`，**经重投影对齐** | 时域信息（相机运动后才有价值）|
| **[55]** | **1** | 历史是否有效 | 投影是否成功 | 重投影失败时，历史特征不可用，网络要忽略它 |

**合计 = 27 + 9 + 9 + 7 + 3 + 1 = 56**

### 2.2 各部分的详细拆解

#### ① [0:27] 邻域 radiance（27 维）

```
来源: in 的 3×3 邻域
     9 个 probe × 每个 probe 同方向格子 3 个数 = 27

怎么用:
   取当前 probe(i,j) 的**同一方向格子 (u,v)**
   + 周围 8 个邻居 probe 在**同一方向 (u,v)** 的值

关键: 【同方向】——和 Lumen 的空间滤波一致
     GatherNeighborRadiance(ScreenTileCoord + Offset, ProbeTexelCoord)
                              ↑ probe 变        ↑ 方向不变

邻域编号（行优先）:
       0 1 2
       3 4 5     → 索引 4 = 中心 → 通道 [4×3:4×3+3] = **[12:15]**
       6 7 8

   索引 4 = **中心 probe** 的 radiance → 这是残差基准
```

## 3. 模型结构

### 3.1 层级（从输入到输出）

```
输入层:   (N, 56)  ← 56 维特征（或 52 维无历史）

隐藏层 ×4:
   Linear(56→64) + ReLU     ← 第1层（输入维度 56）
   Linear(64→64) + ReLU     ← 第2层
   Linear(64→64) + ReLU     ← 第3层
   Linear(64→64) + ReLU     ← 第4层

输出层:   Linear(64→3)       ← 最后一层，**无 ReLU**

残差:     out = center + out
               ↑ x[:, 12:15]（输入中心值）
```

## 4. 训练循环（完整）

### 4.0 一个 batch 从哪来、包含什么 ★核心

#### 抽 batch 的三步

```
第 1 步: 选定 1 帧（比如 frame_000005）
第 2 步: 这帧有 169,984 个有效样本（2656 probe × 64 方向）
第 3 步: 从中【随机无放回】抽 8192 个
         ↓
batch = 特征 (8192, 52) + 真值 (8192, 3)
```

#### 五个关键点

| # | 点 | 说明 |
|---|---|---|
| 1 | **从 1 帧抽** | 不跨帧。一个 batch 内所有样本同属一帧 |
| 2 | **随机抽** | 不是连续块。8192 个样本散布整个 atlas |
| 3 | **无放回** | 帧内不重复采样 |
| 4 | **覆盖率** | 4.8%/次（8192÷169,984）→ 15 轮累计 72.3% |
| 5 | **样本独立** | MLP 无空间依赖，batch 内顺序无关 |

#### 一个 batch 长什么样（举例）

```
样本 1:    probe(12, 34)  方向(3, 5)   ← 画面左下
样本 2:    probe(88,  2)  方向(7, 1)   ← 画面右上
样本 3:    probe(45, 17)  方向(0, 6)   ← 画面中间
样本 4:    probe( 3, 30)  方向(5, 2)   ← 画面左边
...
样本 8192: probe(70, 20)  方向(2, 4)

→ 完全打散：遍布整个画面 + 所有 64 个方向
```

#### 为什么随机抽，而不是连续块？

| 方式 | batch 内样本 | 梯度 | 结果 |
|---|---|---|---|
| 连续块 | 高度相似（同一区域光照接近）| 有偏 | 学歪、收敛慢 |
| **随机（我们）** | 多样（亮/暗、墙角/开阔、有效/无效）| 稳定 | 收敛快、泛化好 |

#### 一个 batch 的数据流

```
feat:   (8192, 52)   ← 56 维特征（当前用 52，未含历史）
           ↓ 模型
pred:   (8192, 3)    ← 预测 radiance
           ↓ 对比
target: (8192, 3)    ← 真值，来自 gt.npy 对应位置
           ↓
loss:   1 个标量      ← relative L2
```

#### batch 在显存里多大？

```
8192 × 52 × 4 字节（float32）= 1.70 MB   ← 特征
8192 ×  3 × 4 字节            = 0.10 MB   ← 真值
                               ≈ 1.8 MB

很小 —— 5060（8GB）轻松跑，瓶颈根本不在显存
```

### 4.1 一次 step（最小单位，6 步）

```python
# ① 前向：算预测
pred = model(feat)               # (8192, 52) → (8192, 3)

# ② 算损失：和真值比
loss = criterion(pred, target)   # relative L2 → 一个标量

# ③ 清梯度
opt.zero_grad(set_to_none=True)

# ④ 反向：算每个参数的梯度
loss.backward()

# ⑤ 裁剪：防更新幅度过大
clip_grad_norm_(model.parameters(), 1.0)

# ⑥ 更新：权重变化（模型"学了一点"）
opt.step()
```

### 4.2 一轮 epoch（49 步）

```
for i, batch in enumerate(dl):
    ↑ 每次取 1 帧，从这帧采 8192 个样本
    → 49 步（49 帧可用）

每轮结束:
    sched.step()        ← 学习率衰减（CosineAnnealing）
    记录 loss 到 jsonl
    若 loss 更低 → 存 best.pt
```

## 8. 训练中的"区别"

### 8.1 每个 step 之间的区别

**数据**：不同的帧（49 帧轮一遍）
**权重**：每步都更新（735 次累积）

所以：同样是 frame_1，第 15 轮看到的模型，比第 1 轮的模型"更聪明"（loss 更低）

### 8.2 每轮 epoch 之间的区别

| 项 | 变化 |
|---|---|
| 数据 | 每轮重新随机采样（同样 49 帧，不同 8192 子集）|
| 学习率 | 每轮衰减（1e-3 → 0）|
| 模型精度 | 逐步提升 |
