# Notes 4：ONNX 中间格式

> 通用知识点。
>
> 目标：搞懂 ONNX 是什么、为什么需要它、模型是怎么"变成"ONNX 的。
>
> 前置：Notes1（初始化）、Notes2（残差）——知道模型由"权重 + 计算流程"组成即可。

---

## 1. ONNX 是什么

**ONNX = Open Neural Network Exchange**（开放神经网络交换格式）

一句话：**深度学习界的"世界语"**——一种框架无关的**模型交换格式**。

```
PyTorch  ──┐
TensorFlow─┼──→  ONNX  ──→  各种推理引擎（TensorRT / onnxruntime / OpenVINO...）
MXNet   ──┘
```

### 它保存什么

| 内容 | 说明 |
|---|---|
| **计算图结构** | 数据从哪进、经过哪些算子、从哪出 |
| **权重（作为常量）** | 训练好的参数，冻结在图里 |

### 它不保存什么

- ❌ Python 代码 / 类的定义
- ❌ 训练逻辑（反向、优化器）
- ❌ 动态控制流（通常被展开）

---

## 2. 为什么需要这个"中间人"

**没有 ONNX 时**：每个推理引擎都要为每种训练框架写解析器

```
TensorRT 要写：PyTorch 解析器、TensorFlow 解析器、MXNet 解析器……（N×M 问题）

有了 ONNX：每个引擎只需认识 ONNX 一种格式（N + M 问题）
```

> **类比**：各国语言 ↔ 世界语 ↔ 各国语言。有 N 种框架 + M 种引擎，ONNX 把 N×M 种翻译需求降到 N+M 种。

---

## 3. ⭐ 导出 ONNX 的本质（重要认知）

> **导出不是"保存代码"，而是"记录数据流 + 冻结权重"**

### 对比

| | 保存的是什么 |
|---|---|
| 训练框架的格式（如 `.pt`）| 权重 + 模型定义（类/函数）|
| **ONNX** | **计算图 + 权重作为常量节点** |

> **想象**：
> - `.pt` = "一本菜谱 + 食材 + 厨师的手艺"
> - ONNX = "一张流水线示意图，标注每道工序和投入的原料"（厨师不在了，但流程还在）

---

## 4. 导出的四个步骤

### 步骤 1：追踪（Trace）

```python
dummy = torch.randn(1, in_dim)      # 假输入
torch.onnx.export(model, dummy, "model.onnx", ...)
```

**原理**：拿一个假输入"走"一遍网络，框架在旁边**记录数据经过了哪些操作**

```
输入 → Linear → ReLU → Linear → ... → 输出
       ↑ 记录这一串操作序列，不是记录 Python 代码怎么写的
```

### 步骤 2：冻结权重

- 训练时：权重是模型属性，**每步都变**
- 导出时：权重被**定格**成图里的常量节点（ONNX 叫 `initializer`）

```
权重从"变量"变成"常量"
```

### 步骤 3：翻译成标准算子

| 框架算子 | ONNX 算子 |
|---|---|
| `nn.Linear` | `Gemm` / `MatMul + Add` |
| `nn.ReLU` | `Relu` |
| 切片 `x[:, a:b]` | `Slice` |
| 相加 `a + b` | `Add` |
| `nn.Conv2d` | `Conv` |

### 步骤 4：序列化成文件

```
结构 → model.onnx
权重 → 可能内联，也可能单独存成 model.onnx.data
```

---

## 5. ONNX 文件的两种形态

### 小模型：单文件

```
model.onnx   （结构 + 权重都在里面）
```

### 大模型：结构 + 外部数据

```
model.onnx          ← 只有结构（几十 KB）
model.onnx.data     ← 权重（可能几 GB）
```

> **踩坑点**：解析时必须保证 `.onnx` 和 `.onnx.data` **在同一目录**，否则报
> `Failed to open file: model.onnx.data`

---

## 6. 动态维度（dynamic_axes）

### 问题

导出时用假输入 `dummy = (1, 52)`，但推理时可能：
- 一次跑 1 个样本
- 一次跑 8192 个
- 一次跑整帧 20 万个

**如果形状写死，换个大小就报错。**

### 解决

```python
torch.onnx.export(
    model, dummy, "model.onnx",
    input_names=["feat"], output_names=["out"],
    dynamic_axes={
        "feat": {0: "num_samples"},      # 第 0 维（样本数）可变
        "out":  {0: "num_samples"},
    },
    opset_version=18,
)
```

**约定**：第 0 维通常是 batch / 样本数，设为动态最实用。

---

## 7. opset（算子集版本）

- `opset_version` 指定用哪一版 ONNX 算子标准
- 版本越高，支持的算子越新，但**兼容性可能下降**

**常见选择**：

| opset | 说明 |
|---|---|
| 11~13 | 老版本，兼容性最好 |
| 17 / 18 | 较新，支持更多算子 |
| ≥ 18 | 新导出器常用，支持最新特性 |

> **踩坑**：导出器可能自动升级 opset 并警告（"Automatic version conversion"）。如果下游引擎不支持高版本 opset，需要显式指定低版本。

## 8. ⭐ 权重的"从活到死"（核心认知）

这是理解"训练 vs 推理"的钥匙：

| 阶段 | 权重的身份 |
|---|---|
| **训练时** | **变量**（每次 `optimizer.step()` 都被修改）|
| **导出 ONNX** | **常量**（冻结进计算图，不再变化）|
| **推理引擎** | **被编译进 kernel**（可能转成 FP16/FP8）|

> **一句话**：训练时权重是"正在被捏的泥巴"，导出后是"烧好的陶器"，推理引擎给它"上了釉"。

---

## 9. ⭐ 权重 vs 输入数据（易混淆）

这是最常见混淆点：

| | 权重 | 输入数据 |
|---|---|---|
| **是什么** | 模型学到的"知识" | 每帧要处理的"原材料" |
| **数量** | 训练后固定（比如 16,067 个）| 每帧可能不同（比如 169,984 个样本）|
| **存哪** | ONNX 的常量节点 / engine | **推理时实时产生，在显存里** |
| **会变吗** | 推理时不变 | 每帧都不同 |
| **作用** | "怎么算"的规则 | "算什么"的内容 |

> **类比**：权重 = 厨师的刀工；输入数据 = 食材。刀工再好，没食材也做不出菜。

## 10. 常见问题速查

| 问题 | 原因 / 解决 |
|---|---|
| 报 `No module named 'onnxscript'` | 新版 PyTorch 导出器依赖它，`pip install onnx onnxscript` |
| 报 `Failed to open file: xxx.onnx.data` | 外部数据文件不在同一目录 |
| 导出后 shape 是静态的 | 忘了设 `dynamic_axes` |
| opset 警告/自动升级 | 显式指定 `opset_version` |
| 导出结果含训练行为 | 忘了 `model.eval()` |
| Unicode 报错（如内部打印 ✅）| 设置 `PYTHONIOENCODING=utf-8` |

---

## 11. 一句话总结

| 问题 | 答案 |
|---|---|
| ONNX 是什么？ | 跨框架的模型交换格式（"世界语"）|
| 解决什么问题？ | 让训练框架和推理引擎解耦（N×M → N+M）|
| 导出做了什么？ | 记录数据流 + 冻结权重成常量 + 翻译成标准算子 |
| 权重变了没？ | 从"变量"变成"常量" |
| 文件有几种？ | 单文件，或 `.onnx` + `.onnx.data` |
| 动态维度？ | 用 `dynamic_axes` 指定哪一维可变 |

## 附：核心清单

```
导出前必做:
  ✓ model.eval()                    # 切推理模式
  ✓ 准备 dummy input                # 让框架追踪形状
  ✓ 设 dynamic_axes                 # 需要可变维度时
  ✓ 指定 opset_version              # 避免自动升级
  ✓ 保证 .onnx 和 .onnx.data 同目录  # 外部数据时

导出产物:
  model.onnx        结构（算子 + 拓扑）
  model.onnx.data   权重（大模型的常量）

导出后权重身份:
  训练: 变量 → 导出: 常量 → 推理引擎: 编译进 kernel
```
