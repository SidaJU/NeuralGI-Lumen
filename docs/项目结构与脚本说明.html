项目结构与脚本说明

NeuralGI-Lumen —— 用神经网络替换 UE Lumen 屏幕探针传统滤波 · 含引擎侧与 Python 侧全链路

0. 项目目标（一句话）

让 Lumen 的屏幕探针在 64 射线输入下，得到接近 256 射线的 GI 画质 —— 用 NN 替换其手工启发式滤波。

最初的设想是"降射线省性能"（64→16），但实测发现 Lumen 的 shader 只编译 Trace=8/16/32 三档，该路线不可行，因此转为画质提升路线。

1. 整体架构（两大块）

闭环：引擎采集数据 → Python 训练 → 导出 onnx → 引擎加载推理 → （需要时再采集新数据迭代）。

7. 三条通路与模型

通路输入 → 答案任务模型
Alow.in → low.gt纯滤波runs/b_full（56 维）
B'low.in → high.gt滤波 + 补射线（部署主力）runs/b_prime_real（56）/ b_nohist（52，当前部署）

9. 重要约束与坑

约束 / 坑说明与对策
★ 替换时机 必须在 ConvertToSH 前替换 radiance；下游消费的是 SH 而非原始 radiance（详见 LOG 第 9 节）
NNE 不支持 CPU 上传官方 NNEDenoiser 只用 shader 写入 buffer → 照搬其三段式
LoadObject 崩溃UObject 只能在 GameThread 创建 → 用 CVar 回调触发 GameThread 预加载
Trace 只有 8/16/32"降射线省性能"不可行 → 转为画质提升路线
两遍采集帧号错位用相机矩阵最近邻配对（匹配距离 0.00e+00）
NNE 无 TensorRT runtime本地 5.6 没有；用 NNERuntimeORTDml（DirectML，≈1ms）
维度 52 / 56 易混换模型时 shader stride 与 CVar 必须同步改
验证"是否生效"用 DebugScale（0/50/1）做因果验证，不要只看日志
