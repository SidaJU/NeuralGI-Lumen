## 0. 项目目标（一句话）

用神经网络替换 Lumen Screen Probe 的传统时空滤波器，让 Lumen 在低射线成本下产出高质量 GI。

> 详细背景见 `README.md`，采集操作见 `方案B-双次采集SOP.md`。

### 2.1 采集流程

每帧渲染时 `EnqueueDump` 被调用一次：

```
① 心跳日志        —— 证明 Lumen 管线确实跑到了这里
② 新一轮判定      —— Enable 0→1 上升沿 或 OutputDir 变化 → 重置计数
③ WaitForMotion  —— 等相机开始运动才编号（消除手动 Enable 的延迟）
④ 正式编号        —— FrameIndex = GFrameCounter++
⑤ 异步写盘        —— 6 路 readback → npy + json
```

### 2.2 产出文件

| 文件 | 形状 | 说明 |
|---|---|---|
| `frame_%06d_in.npy` | (validH, validW, 3) | 滤波前 radiance |
| `frame_%06d_gt.npy` | (validH, validW, 3) | 滤波后 radiance |
| `frame_%06d_hitdist.npy` | (validH, validW) | 射线命中距离 |
| `frame_%06d_depth.npy` | (probeH, probeW) | probe 深度（uint32，需 `asfloat`）|
| `frame_%06d_normal.npy` | (probeH, probeW, 2) | 法线（八面体编码）|
| `frame_%06d_wpos.npy` | (probeH, probeW, 4) | 平移后世界坐标 |
| `frame_%06d.json` | — | 相机矩阵（配对/对齐用）|
| `meta.json` | — | 全局配置（含 `tracing_octahedron_resolution`）|

> **关键**：`in` 和 `gt` 都存了。所以每个目录都有「滤波前 + 滤波后」两套数据 —— 这是方案 A/B/A''/B'' 切换的基础。

## 4. 各脚本详解

### 4.1 采集：`tools/capture/capture_b_pair.py`

**运行环境**：UE 编辑器的 Python 控制台（不是命令行）。

**为什么要它**：编辑器视口不遵守 `Use Fixed Frame Rate`，实时播放会让两遍（快/慢）采样错位。这个脚本改成**逐帧推进** + **tick 回调异步**（不能用 `sleep`，会卡住渲染）。

**核心参数**：

| 参数 | 含义 |
|---|---|
| `num_frames` | 采样点数（不同相机位置）|
| `hold` | 每位置停几个渲染帧（等渲染跟上，**两遍必须相同**）|
| `frame_step` | 采样间隔（0=自动按路径长度铺满）|
| `seq_length` | 路径长度（探测失败时手动指定）|
| `out_prefix` | 输出目录前缀，写到 `<前缀>_low` / `<前缀>_high` |

**用法**：

```python
import sys
sys.path.append('D:/NSPF_Capture')
import capture_b_pair, importlib
importlib.reload(capture_b_pair)

capture_b_pair.run(num_frames=600, hold=1, seq_length=600)
```

### 4.2 数据加载：`tools/dataset/probe_dataset.py`（★ 最核心）

两个类：

| 类 | 职责 |
|---|---|
| `ProbeSequence` | 读单个采集目录，加载帧、解码几何（depth 的 `asfloat`、normal 的八面体解码）|

#### 56 维特征构成

| 通道 | 维度 | 内容 |
|---|---|---|
| `[0:27]` | 27 | 3×3 邻域 radiance（**同方向**，跨 probe）|
| `[27:36]` | 9 | 3×3 邻域 hitdist |
| `[36:45]` | 9 | 3×3 邻域 valid |
| `[45:52]` | 7 | 几何（log 深度 1 + 法线 3 + 相对坐标 3）|
| `[52:55]` | 3 | 历史帧 radiance（相机重投影对齐）|
| `[55]` | 1 | 历史是否有效 |

#### 三个关键机制

**① 时域重投影**
```
当前 probe 的世界坐标 → 用历史帧相机矩阵投影 → 取对应的历史 probe
```

**② 相机矩阵配对**（解决两遍速度不同）
```
不按帧号取 GT，而是按相机矩阵最近邻匹配
```
> 背景：低射线（快）和高射线（慢）每个位置实际采到 ~2.0 vs ~1.9 帧，累积几百次后帧号彻底错位。但两遍走的是同一条轨迹，实测矩阵距离 `0.00e+00`，所以改用矩阵配对。

**③ 方案切换（GT 来源）**

| 方案 | 输入 | 答案 | 学什么 |
|---|---|---|---|
| A | low 的 `in` | low 的 `gt` | 纯滤波 |
| **B'（当前）** | low 的 `in` | high 的 `gt` | 滤波 + 射线（耦合）|
| B''（待做）| low 的 `in` | high 的 `in` | **纯射线提升** |

切换只需改一行：
```python
gt_target = log_normalize(gt_frame["gt"])   # B'
# 改成 gt_frame["in"] 就是 B''
```

### 4.3 训练：`train/`

| 文件 | 内容 |
|---|---|
| `model.py` | `ProbeFilterMLP` |
| `losses.py` | relative L2（主）+ MSE（对照）|
| `train.py` | 主循环 |

**模型结构**：

```
输入 (N, 56)
  → Linear(56→64) + ReLU
  → Linear(64→64) + ReLU   ×3
  → Linear(64→3)            ← 最后一层无 ReLU
  → + x[:, 12:15]           ← 残差：加回输入中心值
输出 (N, 3)
```

参数量：16,323（56 维输入时）

**训练循环**：

```
for epoch in range(15):
    for i, frame in enumerate(dl):        # 每 step = 处理 1 帧
        ① 前向 → ② loss → ③ 清梯度 → ④ 反向 → ⑤ 裁剪 → ⑥ 更新
    学习率余弦衰减 + 存 best.pt
```

每 step 从 1 帧随机采 `samples_per_frame`(8192) 个 texel。

**为什么是 per-texel**：模型对每个 texel 独立处理（MLP 无空间聚合），所以**不依赖 atlas 尺寸** —— 不同分辨率产出的数据可以互相推理。

### 4.4 校验：`tools/verify/`

#### `verify_b_pairing.py`（★ 方案 B 配对 6 项）

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 帧数 / 帧名 | 两边一致 |
| 2 | **相机矩阵逐帧比对** | 偏差 ≈ 0 |
| 3 | 几何（probe 级深度）| 中位差异 < 0.05 |
| 4 | 射线数差异（平滑度）| 高射线更干净 |
| 5 | GT 质量 | GT 优于输入 |
| 6 | **meta 里 tracing 分辨率** | 8 vs 16（4 倍）|

#### `diag_frame_offset.py`

搜索整体偏移 k，判断两遍是「真错位」还是「采样密度不同」。

- 若某个 k 让偏差 ≈ 0 → 只是整体错开 N 帧
- 若最小值仍很大 → 速度真的不同（应用矩阵配对）

#### `pair_by_camera.py`

验证「用相机矩阵能否配对」——报告匹配距离和索引比。

### 4.5 推理（首选）：`tools/eval/run_infer.py`

**枚举式调用** —— 不再临时拼参数：

```bat
python tools\eval\run_infer.py --list                                  :: 查看所有可选项
python tools\eval\run_infer.py --scheme A  --scene train --frames 150
python tools\eval\run_infer.py --scheme B2 --scene new   --frames 30 300
```

两个维度即可：

| 维度 | 取值 | 含义 |
|---|---|---|
| `--scheme` | `A` / `B` / `B2` | 方案：纯滤波 / 滤波+补射线 / 纯补射线 |
| `--scene` | `train` / `new` | 场景：原场景（见过）/ 新场景（泛化验证）|

方案与模型、数据的映射写在脚本顶部的注册表里（`SCHEMES` / `SCENES` / `MODELS`），新增方案只需改注册表。

**输出规范**：

```
output/<场景>/<方案>_f<帧号>.png
```

每张图标题自带完整标注（方案 / 模型 / 数据 / 帧号 / 三个平滑度 / 完成度），单独打开即可 self-explain。

### 4.6 评估：`eval/eval_smoothness.py` + `tools/eval/visualize_b.py`

**核心指标**：

```
完成度 = (输入平滑度 − 模型输出) ÷ (输入平滑度 − GT平滑度) × 100%
```

| 完成度 | 含义 |
|---|---|
| ≈ 100% | 完全达到 GT |
| **> 100%** | ⚠️ 过度平滑（可能抹掉细节，需看图确认）|
| 60~80% | 尚可 |
| < 50% | 没学到 |

**同时看 MSE / relL2**：平滑度是相对指标，必须配合绝对误差一起判断。

> 平滑度定义与 `Notes6-完整训练流程.md` 一致：方向维度相邻差异 ÷ 均值，**越低越干净**。

**`visualize_b.py`** 生成「输入 / 模型输出 / GT」三连图 —— 数字看不出「细节有没有被抹掉」，必须看图。

## 8. 重要约束（踩过的坑）

| 约束 | 说明 |
|---|---|
| `hold` 两遍必须相同 | 不同 → 「帧号→位置」映射不同 → 必然错位 |
| `Trace` 只能 8/16/32 | shader permutation 限制，没有 4 |
| `Trace < Gather` 会崩 | 上采样未实现，画面变蓝 |
| 帧号错位 ≠ 数据错位 | 用相机矩阵配对绕开 |
| 分辨率可变 | 但 `DownsampleFactor` 和 `GatherRes` 不能变 |
| 编辑器视口不遵守 FixedFrameRate | 所以采集必须逐帧步进 |
